What is VeldraDB?

Welcome to VeldraDB, the world's first embedded database designed exclusively from the ground up for Enterprise Game Engines.

Traditional SQL databases (like MySQL) or document stores (MongoDB) are built over a network, creating milliseconds of latency per query. In game development, where a frame must render in 16ms, network delays are unacceptable.

VeldraDB behaves like SQLite: it is 100% embedded in your game's memory. However, instead of using traditional relational tables, it organizes data using an Entity Component System (ECS) approach. This ensures data is contiguous in RAM (Archetypes), allowing for instant CPU cache hits and millions of operations per second directly inside your game loop.

💡 Key Takeaway: VeldraDB perfectly blends the durability of a database (writing to disk safely) with the lightning speed of an in-memory game state engine.

Unity / C# Integration

VeldraDB binds natively to C# via P/Invoke. It is garbage-collector (GC) friendly, as the memory is managed entirely in the C++ backend.

using Veldra; // Require VeldraDB.cs in your project

public class GameManager {
    VeldraDB db;
    
    public void LoadGame() {
        // Instantly maps the 4KB pages from disk to RAM
        db = new VeldraDB("saves/world1.vdb"); 
        
        // Native interaction
        db.Query("SPAWN PREFAB 'player' WITH health = 100, tag = 'hero';");
    }
    
    public void OnDestroy() {
        db.Dispose(); // Sycnchronizes pending changes back to disk
    }
}

Unreal Engine / Native C++

For custom C++ engines or Unreal, you link against the static VeldraDB lib. This grants absolute zero-overhead direct memory access to the ECS archetypes.

#include "core/veldra.h"

int main() {
    veldradb::Database db("saves/world1.vdb");
    db.query("SPAWN PREFAB 'boss' WITH health = 10000;");
    return 0; // Autosaves on destruction
}

Python Binding (AI & Data Science)

Great for training AI models on your game's telemetry data or scripting map generators.

import veldradb

# Connects to the exact same file your game uses
db = veldradb.connect("saves/world1.vdb")

# Fetch telemetry logic
rows = db.query("SELECT id, health FROM entities WHERE tag = 'enemy';")
for row in rows:
    print(f"Enemy {row['id']} has {row['health']} HP")

Go Binding (Microservices & Multiplayer)

If you are building an authoritative backend server for multiplayer, the Go bindings provide thread-safe access.

package main

import (
    "fmt"
    "github.com/veldradb/go-veldra"
)

func main() {
    db, _ := veldra.Open("saves/world1.vdb")
    defer db.Close()
    
    result := db.Query("FIND entities NEAR (0.0, 0.0, 0.0) WITHIN 50.0")
    fmt.Println(result)
}

GQL Reference: Schema Definition

VeldraDB supports explicit tables or dynamic entity injections. Standard schema logic applies:

CREATE TABLE

CREATE TABLE players (
    id INT,
    health FLOAT,
    tag STRING
);

DROP TABLE

DROP TABLE players;

GQL Reference: Spawning & Insertion

Instead of rigid SQL INSERTS, GQL allows dynamic ECS combinations.

SPAWN PREFAB

The standard way to drop objects into the game world.

-- Automatically injects components into an archetype
SPAWN PREFAB 'goblin' WITH health = 100, pos_x = 10.5, pos_y = 0.0;

INSERT INTO

Standard SQL-like insertion if you prefer strict schemas.

INSERT INTO entities (id, tag, health) VALUES (1, 'enemy', 50.0);

GQL Reference: Querying & Spatial Logic

This is VeldraDB's superpower. The engine includes an explicit `FIND NEAR` spatial hash grid system resolving spatial math in $O(1)$ time.

SELECT

Standard data fetching.

SELECT id, health FROM players WHERE health > 0 ORDER BY health DESC LIMIT 10;

FIND NEAR (Spatial Query)

Locates physical entities inside a 3D sphere.
Important: Coordinates must be explicitly defined as floating-point numerals (e.g. `10.0`, not `10`).

-- Fireball explosion logic
FIND entities NEAR (10.0, 0.0, 5.0) WITHIN 50.0 WHERE tag = 'enemy';

GQL Reference: Modifying State

UPDATE

Apply mathematical changes across massive arrays of entities instantly.

-- Damage all enemies at once
UPDATE entities SET health = health - 50.0 WHERE tag = 'enemy';

DELETE

Remove entities from RAM and disk.

-- Garbage collect dead bodies
DELETE FROM entities WHERE health <= 0.0;

GQL Reference: World State Management

VeldraDB allows native game-state saving and loading bypassing all OS overhead by creating direct Memory Page snapshots.

SNAPSHOT (Quick Save)

-- Duplicates the current Archetype RAM explicitly to disk slot
SNAPSHOT TO 'slot1_quicksave';

RESTORE (Quick Load)

-- Wipes current memory and re-mounts the slot in microseconds
RESTORE FROM 'slot1_quicksave';

Veldra Studio (Desktop IDE)

VeldraDB ships with a completely native, offline, developer IDE to help game designers visualize the `.vdb` files directly without writing code.

🚀 Quick Access: If the local background engine is running, you can access the IDE directly right now!

Launch Veldra Studio

To start the server manually via CLI:

veldra.exe serve -port 8080 my_world.vdb

The studio boasts full Intellisense UI, syntax highlighting, and an execution planner to debug your game worlds visually.
