The 5-Minute Quickstart

Go from nothing to a live simulation in 3 easy steps.

Step 1

Native Engine Init

Run install.bat. This registers flux.dll globally so your game can find it instantly.

Step 2

Setup Bindings

Pick your language and setup the connection. For Python:

from fluxdb import FluxDB
# 1. Start the world
db = FluxDB() 
# 2. Add some data
db.query("SPAWN PREFAB 'p' WITH hp=100;")
  • Line 1: Imports the high-performance native wrapper.
  • Line 3: Initializes the memory world and page manager.
  • Line 5: Executes an atomic SPAWN command at microsecond speed.

🎮 C# / Unity Integration

using Flux;

var db = new FluxDB();
// Spawn at specific coordinates
db.Query("SPAWN PREFAB 'player' WITH x=10, y=0, z=5;");
  • Line 1: Accesses the Flux namespace (from UPM package).
  • Line 3: Opens a handle to the native binary engine.
  • Line 5: Passes the GQL string through the P/Invoke layer to C++.

Spatial Indexing (The Secret Sauce)

Unlike standard SQL, FluxDB understands 3D space. It uses a Native Octree to ensure that spatial queries never scan the whole database.

The FIND Command

FIND entities NEAR (10, 0, 5) WITHIN 50.0 WHERE health > 0;

FluxDB calculates the AABB of your request and only checks entities in relevant Octree nodes. Average latency: 12 microseconds.

GQL Command Reference

The Game Query Language is structured like SQL but optimized for the ECS architecture.

Command Purpose Example
CREATE TABLE Defines an Archetype structure. CREATE TABLE players (id INT, hp FLOAT);
SPAWN Instantiates an entity into an archetype. SPAWN PREFAB 'hero' WITH hp=100.0;
SELECT Retrieves data with vector-scanned speed. SELECT * FROM players WHERE hp < 50;
UPDATE Modifies entity components in-place. UPDATE players SET hp = 100 WHERE id = 1;
FIND NEAR Spatial lookup using native Octree. FIND entities NEAR (0,0,0) WITHIN 10;
LISTEN Reactive subscription to world events. LISTEN SELECT * WHERE distance < 50;
AT TICK Temporal query for Deterministic Replay. SELECT * AT TICK 500;

Language Setup & Installation

FluxDB is a global primitive. Install once, use everywhere.

C++
Native Core

Global System Install

To use FluxDB in native C++ projects or to provide the foundation for other languages:

# 1. Clone the repo and enter directory
# 2. Run the installer (requires G++)
.\install.bat

This compiles flux.dll, copies headers to C:\FluxDB\include, and sets the FLUX_PATH environment variable.

PYTHON
Data Science & Scripting

PIP Installation

Install the pre-compiled high-performance wrapper:

# Install from the release wheel
pip install fluxdb-1.0.0-py3-none-any.whl

The Python binding automatically finds the global flux.dll using the system path.

UNITY
Game Engine (UPM)

Unity Package Manager

  1. Open Window > Package Manager.
  2. Click + and select Add package from disk....
  3. Select the package.json inside the unity/ folder of the release.

FluxDB components will appear in your "Add Component" menu instantly.

UNREAL
Game Engine (Plugin)

Plugin Integration

Copy the unreal/FluxDB folder into your project's Plugins/ directory. Regenerate project files and you're ready to go.

// Access via C++ or Blueprints
UFluxDBSubsystem* DB = GEngine->GetEngineSubsystem<UFluxDBSubsystem>();
DB->Query("SELECT * FROM players;");

Source Code Protection

FluxDB includes pro-grade scripts to automate your distribution pipeline without exposing your internal C++ algorithms.

Distributor Tool

create_binary_dist.bat

Run this script to generate a dist_global/ folder. This folder is what you share with other developers. It includes:

  • Compiled flux.dll (The Engine)
  • Python Wheels (.whl) for clean pip install
  • UPM Package for Unity (Native bindings)
  • Binary-only Unreal Plugin

Your .cpp files never leave your machine.
